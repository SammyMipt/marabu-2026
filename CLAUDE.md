# Инструкции по проекту

Веб-презентации двух лекций для детского лагеря Марабу (лето 2026, Массачусетс): **«Электрон»** для младших (11–14) и **«Течения и турбулентность»** для старших (14–18). Автор лекций — пользователь, приглашённый лектор.

**Начните с [WORK.md](WORK.md)**: там состояние по беатам, порядок работы, принятые решения с обоснованиями, карта готовых демок в `Demo/` и открытые вопросы. Устройство кода — в [README.md](README.md), правила текста слайдов — в [STYLE.md](STYLE.md).

## Что нужно знать до первой правки

**Планы лекций — канон.** `lekciya_elektron_plan.md`, `lekciya_turbulentnost_plan.md` и `marabu_kontekst.md` содержат замысел, тайминг, авторские формулировки и обоснования всех решений. Контент слайдов следует им; отклонения — только через явное обсуждение с автором. Ничего не досочинять: числа, фамилии и факты берутся оттуда.

**Пользователь крайне чувствителен к «слопу».** Первая версия презентаций была забракована как generic и AI-generated. Читайте [STYLE.md](STYLE.md) до того, как писать текст на слайд: никаких ровных троек буллетов, тире-связок для ритма, оборотов вроде «на самом деле» и «не просто X, а Y». Авторские формулировки из планов («волна шансов», «внутри всех вещей есть что-то мелкое и заряженное») сохраняются дословно — это интонация лектора, её не улучшают.

**Слайд — не конспект.** Методика, реквизит, тайминг и режиссёрские ходы идут в `notes` (режим докладчика, клавиша `S`), а не на проектор.

**Offline-first — жёсткое требование.** Лагерь, чужой проектор, ненадёжный Wi-Fi. Всё работает с диска: библиотеки и медиа вендорятся в репозиторий. Единственное исключение — одна вставка YouTube, и в заметках честно сказано, что ей нужна сеть.

**Node.js на машинах автора нет.** Никаких этапов сборки, npm-скриптов и бандлеров. Всё открывается двойным кликом по HTML.

**Ссылки не выдумывать.** Любой URL на видео или источник проверяется реальным открытием страницы. Лучше честное «свободного видео не существует», чем правдоподобная битая ссылка.

## Порядок работы

Наполняем **по одному беату за подход**: материалы → текст по STYLE.md → демка, если нужна → показ автору → правки → **явное согласие** → коммит. Без согласия не коммитить; один беат — один коммит.

Сообщения коммитов на русском, как и весь проект.

## Проверка изменений

Открывать колоду в браузере и смотреть глазами, а не полагаться на то, что код выглядит правильным. Полезное:

- Превью-панель агрессивно кеширует `slides.js` и `deck.js`. Если правки не видны — открыть в новой вкладке либо через временную страницу с `fetch(..., {cache:'no-store'})` и `eval`.
- `requestAnimationFrame` не тикает, пока вкладка скрыта: демка в фоне выглядит замёрзшей — это не баг.
- В демках есть `window.__demoState` — точка входа для проверок из консоли.

## Git

Ветка `main`, remote — `https://github.com/SammyMipt/marabu-2026`. На новой машине аутентификация настраивается один раз (дальше вход через браузер, пароли вводить не нужно):

```bash
git config --global credential.helper manager
git config --global credential.https://github.com.provider github
git config --global credential.https://github.com.gitHubAuthModes browser
```
